## Fix: Thinking bubble doesn't render

### Root causes (confirmed by reading code)
1. **CSS layout (affects all responses)** — `.msg` is `display:flex` as a horizontal row. The bubble is inserted as a child *inside* `.msg`, so it renders beside `.msg-body` instead of stacked above. Unsized in a row → invisible/squashed.
2. **Wrong target element for action responses (your payload)** — streaming `STREAM_DONE` attaches the bubble to `streamSession.msgEl` (the streamed-text element, empty for action-only responses). The answer text is rendered separately by `handleStreamActions`, which never gets the bubble.

### Fix

**1. CSS (`extension/styles.css`)** — make `.msg-assistant` wrap + give the bubble full width so it stacks above the body:
- `.msg-assistant { flex-wrap: wrap; align-items: flex-start; }`
- `.msg-thinking-bubble { flex: 1 1 100%; }` (full row → wraps to its own line above `.msg-body`)

**2. Sidepanel (`extension/sidepanel.js`)** — attach the bubble to the element that actually shows the answer, in every path:
- **Action responses**: in `handleStreamActions`, when adding the `done.response` answer message, capture the returned element and call `addReasoningBubble(el, reasoning)` on it. This is the correct target for your `extract`+`done` payload.
- Keep the existing `streamSession.msgEl` attachment for plain-text streaming responses (where `msgEl` *does* hold the answer) — but it now renders correctly once CSS is fixed.
- Apply the same to the non-streaming `askZo` fallback path (already done in prior round, but verify it targets the answer element).

**3. Real DOM test (the missing verification)** — my prior tests only grepped strings. Add a test in `tests/sidepanel.test.ts` that actually exercises the logic. Since sidepanel.js needs a DOM + `chrome.*` (can't import directly), use a **jsdom-based harness**:
- Load sidepanel source, extract `addReasoningBubble` + `markdownToHtml` + `safeText` via the same `vm` extraction pattern used in `tests/sse-parsing.test.ts`, run against a jsdom document.
- Assert: given a `.msg.msg-assistant > .msg-body` element + reasoning text, the bubble is inserted **before** `.msg-body`, has class `msg-thinking-bubble`, contains a `thinking-toggle` with the char count, the `thinking-content` is `hidden` by default, and clicking the toggle reveals it.
- Also assert the no-op: empty reasoning → no bubble added; element unchanged.

If jsdom isn't a dependency, fall back to a **happydom** or a hand-rolled minimal DOM stub (createElement/appendChild/insertBefore/querySelector/setAttribute) — verify which is available in `package.json` first and use whichever exists; if neither, the minimal stub is sufficient for this logic.
