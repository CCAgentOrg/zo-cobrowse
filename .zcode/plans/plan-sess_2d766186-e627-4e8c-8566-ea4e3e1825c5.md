# Mode System — unify presets + personaMode + intent into one explicit Mode

## Goal
Collapse three overlapping concepts (presets, `personaMode` badge, invisible `intent`/`classifyIntent`) into **one explicit, user-chosen Mode** that is the single source of truth for "how Zo behaves and what page context it gets." Bake in the token-efficiency wins from the brainstorm: per-Mode **context tiers** (the push/pull lever), a **compact action schema** (shipped only when the Mode needs actions), and a **compact element+selector list** (fixes the selector-hallucination gap).

## New architecture

### Context tiers (the push/pull lever, fixed per-Mode as you chose)
- **0 — pointer**: URL + title + viewport only (~15 tokens). *(reserved; no built-in mode uses it today — enabling it for repeat-URL turns is deferred, see Out-of-scope)*
- **1 — +text**: add `visibleText` sliced to `mode.textBudget`
- **2 — +elements**: add compact clickable + form-field list **with selectors**: `[a "Full Overview" a.nav-link][button "Search" #btn-search][input #q "Search…" type=text]`
- **3 — +screenshot**: add the screenshot (replaces text-heavy context for visual questions)

     const m = mode || resolveMode(DEFAULT_MODE_ID, customModes);
     const parts = [m.systemPrompt, '', `## Page`, `- URL: ${pageContext.url}`, `- Title: ${pageContext.title}`, `- Viewport: ${pageContext.viewport?.w||'?'}x${pageContext.viewport?.h||'?'}`];

## Token outcome (the point of the exercise)
For the sample "Summarize" on the BoBBreach page, today (full template, because a persona is selected → `classifyIntent` skipped): **~1350 tokens** (225 fixed overhead + ~1000 text + ~130 schema). After this change in Summarize mode (tier 1, textBudget 2000, compact schema): **~580 tokens** — and a one-line `done` JSON instead of the full 130-token commented schema block. For action tasks, the compact element list replaces the screenshot, fixing selector accuracy while cutting the largest cost.
