## Goal

Create `tests/test-prompts/` — a self-contained test-data + harness folder that captures **real streaming responses from the Zo `/zo/ask` API** (using `ZO_API_KEY`) for the full range of zo-cobrowse use cases, and replays those captures through the extension's **real stream parsers** to guard stream-response handling.

This directly fills the gap called out in `extension/background.js:949-952` ("the repo has never captured a real chunk") and turns the existing *synthetic* SSE coverage (`tests/sse-parsing.test.ts`) into *recorded-golden* coverage.

## Folder layout (all net-new under `tests/`)

├── qa-notes.md                # findings from the live captures: exact event/field shapes Zo returned

## Implementation steps

1. **Scaffold** — create the folder, `prompts.json` (use-cases above, derived from the Mode system), `schema.ts` (Zod), and `README.md`.

2. **`capture.ts`** — reads key from `process.env.ZO_API_KEY` (secondary `ZO_ACCESS_TOKEN` for sync-presets parity; load via `bun --env-file=.env`). For each catalog entry, builds the exact prompt the extension would send — importing real `BUILTIN_MODES`, `ACTION_SCHEMA_COMPACT`/`PLAIN_RESPONSE_HINT`, and `shouldDowngradeToJsonDisabled`/`detectIntent` from `extension/lib/*` — then `POST https://api.zo.computer/zo/ask` with `Authorization: Bearer <key>`, `stream:true`, `Accept: text/event-stream`. Saves: normalized raw `.sse` (auth never written) and a `.json` metadata file (request prompt + model used, `x-conversation-id`, `content-type`, observed event/field shapes, assembled final text). Prints a discovery summary (events seen, first-chunk field keys, whether `End` carried `output`, actions/reasoning presence).

3. **Live capture run** — run `bun --env-file=.env tests/test-prompts/capture.ts` against the real API with `ZO_API_KEY` (present in gitignored `.env`). Inspect the outputs and write `qa-notes.md`: the exact stream shapes Zo actually emitted per use case (event types, field keys, `End` payload, key-first vs type-first actions, whether reasoning streamed incrementally vs only in `End`). Adjust `schema.ts` if reality differs from assumptions. Commit the **auth-scrubbed** captures.

4. **`replay.ts`** — mirror the `tests/sse-parsing.test.ts` approach: vm-extract the **real** `safeText`, `extractStreamContent`, and `finishStream` (+ `normalizeActions` from `lib/modes.js`) from `extension/background.js`, faithfully reproducing the production byte-loop edges (`event:` with/without space, blank/comment lines, `[DONE]`, plain-text data lines, `End` empty vs `data.output`, stream-close fallback). Output: the `STREAM_CHUNK`/`STREAM_DONE`/`STREAM_ERROR` sequence the extension would emit.

5. **Tests** —
   - `stream-catalog.test.ts`: `prompts.json` covers all 6 `BUILTIN_MODES` ids + both cobrowse intents (action + read-only), and each entry's tier/expectJson matches its Mode.
   - `stream-replay.test.ts`: for every committed `fixtures/*.sse` — (a) validates the event sequence against the Zod fixture schema; (b) replays and asserts a terminal `STREAM_DONE` arrives (or `STREAM_ERROR` for error fixtures); (c) `fullText` is non-empty and contains **no raw `{reasoning/actions` JSON dump** (the historical raw-JSON-in-chat leak); (d) `actions` are normalized to type-first via `normalizeActions`; (e) `reasoning` is surfaced in `STREAM_DONE` when present. Fixtures committed so CI runs deterministically without a key.

6. **Synthetic error fixtures** — hand-written `synthetic/*.sse` for the invalid-token / 4xx / 5xx-retry paths (deterministic, no key).

7. **Wire-up + verify** — add `"capture:prompts": "bun --env-file=.env tests/test-prompts/capture.ts"` to `package.json`. Run `bun run verify` (full suite + lint + transpile) → **0 failures**, and commit.

## Decisions taken (defaults, since the clarifying questions weren't answered)

- **Validation depth**: replay captured SSE through the vm-extracted real parsers (matches the established `sse-parsing.test.ts` pattern); no `_askZoStreamImpl` mock-fetch harness this round.
- **Discovered gaps**: documented in `qa-notes.md` and frozen as regression fixtures; **no extension code changes** this round (keeps scope contained — a separate follow-up can fix any real mismatch found).
- **Fixtures**: real, auth-scrubbed captures are **committed** so `bun run verify` / CI gate stream handling deterministically. The token is never written to disk or committed.

## In scope / out of scope

- **In**: all net-new files under `tests/test-prompts/`, one `package.json` script, one live-API capture run using the existing `ZO_API_KEY`.
- **Out**: changes to `extension/*` runtime code; changes to existing `tests/sse-parsing.test.ts`; any new dependency (Zod already a devDependency; bun runs TS natively).
