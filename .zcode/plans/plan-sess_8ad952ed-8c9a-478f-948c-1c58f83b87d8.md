# Plan — Live three-channel streaming (Thought / Explored / Final)

## Problem (verified)

The extension's SSE parser was built against a **documented protocol the live API never emits**. Real captures (`tests/test-prompts/fixtures/*.sse`, 2026-08-09) prove:

- `PartDeltaEvent` carries `delta.content_delta` **and** `delta.part_delta_kind` (`"thinking"` vs `"text"`). `background.js:79-101` extracts `content_delta` but **never routes on `part_delta_kind`** → thinking tokens and answer tokens are concatenated into one `fullText`.
- `PartStartEvent` carries the **first token** of each part (`part.part_kind`) — currently dropped, so the first word of every part is lost.
- `FunctionToolCallEvent` / `FunctionToolResultEvent` (the "Explored" tools in the Zo UI) are **completely ignored**.
- Terminal is `event: completed`, not `End` — today only the stream-close fallback at `background.js:989` saves it.
- Reasoning is rendered **once** at `STREAM_DONE` (`sidepanel.js:2046`) as a collapsed `💭 Thought` header; there is **no incremental reasoning path**. That is exactly "thought streams as a single chunk with no separation."

The Zo UI separates three live channels — Thought, Explored, Final. This change brings the extension to parity: reasoning streams token-by-token, tool calls stream as they happen, and the answer text streams separately.

## Approach

Add a `part_delta_kind` router to the byte-loop and emit three per-channel message types over the existing `cobrowse-stream` port. These port messages are **outside** the `MESSAGE_TYPES` contract test (that guards `chrome.runtime.sendMessage`, not port messages), so no contract-test churn.

New port message types:
- `STREAM_REASONING` — `{ sessionId, type, text }` (cumulative thinking-channel text)
- `STREAM_TOOL` — `{ sessionId, type, phase: 'call'|'result', callId?, toolName?, args?, result?, outcome? }` (per FunctionTool event)
- `STREAM_CHUNK` — unchanged (answer/text channel only now)
- `STREAM_DONE` — unchanged shape, but `reasoning` is now the live-streamed thinking and `actions` is unwrapped from the code-fenced envelope.

## Changes

### 1. `extension/background.js` — parse the real protocol

**a. Add part-tracking state in `_askZoStreamImpl` (before the loop, ~`:878`):**
```js
const partKinds = {};   // index -> 'thinking' | 'text' | 'tool-call' | 'tool-return'
let reasoningText = ''; // accumulated thinking channel
```

**b. Add explicit event handlers inside the `data:` branch (replace the catch-all default).** Keep the existing `End`/`Error`/legacy/`[DONE]` branches for backward compat with synthetic fixtures, then add (before the generic fallback):
- `PartStartEvent`: record `partKinds[index] = part.part_kind`; route `part.content` by kind → thinking appends to `reasoningText` + posts `STREAM_REASONING`; text appends to `fullText` + posts `STREAM_CHUNK`.
- `PartDeltaEvent`: `kind = delta.part_delta_kind || partKinds[index]`; route `delta.content_delta` the same way. (`content` extraction via `extractStreamContent` stays as the fallback for unknown shapes.)
- `FunctionToolCallEvent`: post `STREAM_TOOL { phase:'call', callId: part.tool_call_id, toolName: part.tool_name, args: part.args }`.
- `FunctionToolResultEvent`: post `STREAM_TOOL { phase:'result', callId: part.tool_call_id??, toolName: part.tool_name, outcome: result.outcome, result: summarizeToolResult(result) }` (truncate long stdout to ~300 chars).
- `AgentRuntimeStreamChunk`: parsed for shape diagnostics only (not rendered — live reasoning replaces the "Thinking…" badge). Still clears the thinking liveness timeout.
- `completed`: `finishStream(port, sid, fullText, { reasoning: reasoningText })`; `return;` (true terminal — no reliance on the stream-close fallback).

**c. Pass accumulated reasoning on the fallback path too:** `background.js:989` → `finishStream(port, sid, fullText, { reasoning: reasoningText })`.

**d. `finishStream(port, sid, output, extra = {})` (`:1019`)** — add an optional `extra.reasoning`:
- `reasoning = safeText(extra.reasoning) || parsed.reasoning || ''` (live-streamed wins; envelope is fallback).
- Strip a single leading ```` ```json … ``` ```` fence before `JSON.parse` (cobrowse wraps the action envelope this way) via a new `stripCodeFence(str)` helper that only strips when the whole string is one fenced block; on parse failure, `plainText` keeps the **original** (fenced) string so read-only markdown answers survive.
- Keep the existing `doneAction.response || plainText || reasoning` precedence and the `emitStreamDiagnostic` call.

### 2. `extension/lib/modes.js` — `normalizeActions` (`:185`)

Handle the `{"action":"click", …}` singular variant seen in real multi-action captures (qa-notes.md §"Action envelope shape"). In the unknown-shape branch, before skipping, treat a top-level `action` string that names a known type as `type`:
```js
if (typeof a.action === 'string' && ACTION_TYPE_NAMES.includes(a.action)) {
  const { action, ...rest } = a; out.push({ type: action, ...rest }); found = true;
}
```

### 3. `extension/sidepanel.js` — render three live channels

**a. Extend `streamSession` (`:1877`)** with `reasoningEl`, `toolsEl`, `reasoningText` fields.

**b. `STREAM_REASONING` handler:** lazily create a `.msg-reasoning-stream` region **above** `.msg-body` (expanded, label `💭 Thought`) via `ensureReasoningRegion(msgEl)`; set its `.innerHTML = markdownToHtml(cumulative)` each tick. Streams visibly while active.

**c. `STREAM_TOOL` handler:** lazily create a `.msg-explored` region (`🔍 Explored`) between reasoning and body via `ensureToolRegion(msgEl)`. On `phase:'call'` append a card `▸ <toolName> — <args snippet> …` (pending). On `phase:'result'` mark the matching card `✓`/`✗` and stash the (truncated) result in a collapsible `<details>`.

**d. `STREAM_DONE` handler (`:1977`):**
- If reasoning streamed (region has content) **and** is long, convert the streaming region into the existing collapsed `💭 Thought` header (`addReasoningBubble` with `msg.reasoning`); if short, leave it inline. If no reasoning streamed, fall back to `addReasoningBubble(msg.reasoning)` as today.
- Final answer body + action timeline logic unchanged (the placeholder → `responseText` / action-timeline behavior at `:2008-2063` stays).

Visual order inside `.msg-assistant`: `Thought → Explored → Final body → footer` — matching the Zo UI.

**e. Persistence (`:2066`):** add `tools` (the explored list) to the saved assistant message and re-render the explored region in `renderCurrentConversation`/`switchToConversation` (best-effort; reasoning persistence already exists).

### 4. `extension/styles.css`

Add styles for `.msg-reasoning-stream`, `.msg-explored`, `.msg-tool-card` and its pending/done/error states, reusing the muted/collapsible aesthetic already used by `.msg-reasoning` and `.msg-action-run`.

### 5. `extension/AGENTS.md` — fix the documented protocol (`:35-37`)

Replace the stale `FrontendModelResponse`/`End`/`Error` description with the real events: `PartStartEvent`, `PartDeltaEvent` (`part_delta_kind` thinking/text), `FunctionToolCallEvent`/`Result`, `AgentRuntimeStreamChunk`, terminal `completed`.
